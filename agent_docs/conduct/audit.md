# Conduct checklist — /flow-next:audit

A correct run walks `.flow/memory/` plus the glossary, verifies each entry against current code, and decides Keep / Update / Consolidate / Replace / Delete / Harden per entry.

- [ ] The full audit report is printed to stdout as markdown — the counts block (Scanned / Kept / Updated / Consolidated / Replaced / Deleted / Hardened / Marked stale / Skipped legacy, with `(of which retrieval fixes: N)`) plus per-entry detail and the Glossary section. A run that summarizes internally and emits a one-liner has broken this.
- [ ] Legacy flat files at the memory root and any `_*` directory are skipped with a counted warning that points at `/flow-next:memory-migrate`, not audited in place.
- [ ] Harden: under `mode:autofix` candidates appear only under Recommended, with no gate artifact written and no entry demoted; otherwise `flowctl memory mark-hardened` appears only after the transcript shows the gate verified live, and a failed verification leaves the entry active as a failed graduation. No entry file is removed on Harden, and a superseded decision is marked `decision_status: superseded` with `superseded_by`, never `git rm`'d.
- [ ] Genuinely ambiguous classifications in autofix reach `flowctl memory mark-stale <id> --reason "..."` rather than a guessed action; borderline entries are never deleted on that track.
- [ ] Lessons arriving at the store pass the three intake filters: a mechanizable lesson surfaces as a gate proposal, a lesson banks only when it routes to something the transcript touched, and a rule that existed but did not fire gets a retrieval fix, not a rewrite.
- [ ] A correct, recurring, non-mechanizable entry with a nameable defect in its retrieval surface is classified Update with the retrieval-fix variant (title, tags, module, `applies_when`, placement), and the retrieval rationale licenses no body rewrite. Recurrence without a nameable defect falls through to the ordinary reference-drift check, where Keep is correct.
